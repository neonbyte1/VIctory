## Description

## Summary
Console command-list pipeline syncs (`LIST_FUNCTIONS` slots 129/130 and `NEWER_LIST_FUNCTIONS` slots 131/132/146) previously resolved to an empty no-op `sync` with a comment stating that host lists order their own work and every submission is waited for. While submissions are waited for between command lists, D3D12 does not implicitly synchronize dependent UAV reads/writes between consecutive `Dispatch` / `Draw` calls recorded within the same command list without an explicit UAV barrier (`D3D12_RESOURCE_BARRIER_TYPE_UAV`).

This PR makes `sync` emit a global `UAV_BARRIER` via the same `wait_for_shader_writes(this)` helper used by `barrier_groups` (related to #732, though not yet measured in-world).

## Changes
- `crates/victory-gpu/src/list.rs`:
  - Extracted `wait_for_shader_writes(this)` shared by `sync` and `barrier_groups`, emitting `UAV_BARRIER` on `host_list(this)` while safely no-oping when `this` is null, `host` is `None`, or on non-Windows targets.
  - Kept clean-room parity with `barrier_groups` and `resource_barrier` by not decoding undocumented console `flags`/`control` bitfields without title measurements.
  - Added `list::tests::sync_is_safe_on_null_and_non_host_lists` (verifies `LIST_FUNCTIONS` slots 129/130, `NEWER_LIST_FUNCTIONS` slots 131/132/146, null `this`, and `host: None` lists).
  - Added `list::tests::sync_orders_dependent_compute_uav_dispatches` (live D3D12 `cs_5_1` 4-stage dependent compute dispatches through `sync` / `barrier_groups` under the D3D12 Debug Layer — verifies API validity, slot wiring, and end-to-end correctness; does not force hardware overlap on drivers that serialize compute work by default).
