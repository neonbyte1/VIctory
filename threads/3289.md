# Marvisak/VIctory#3289: GPU: a refresh takes the whole pages it touches

- PR by @QalityDev, opened 2026-11-26T16:02:41Z, state **open**
- <https://github.com/Marvisak/VIctory/pull/3289>
- Archived copy; the original thread is authoritative while it exists.

## Description

A refresh of a range that cuts a 64 KiB page copied that part and left the page changed (`Tracked::take`), so every later refresh reaching it copied it again, whether or not the title had written it since. GTA VI refreshes small ranges inside its 174 MB GPU-heap buffer dozens of times per frame: on an RTX 4060 Ti, 410-550 MB of the 550-690 MB copied per frame came from such partial pages.

`Shadow::update` now widens the range to the whole pages it touches (cut to the copy). Taken whole, a page is guarded and copied again only once the title writes it. Ranges whose shaders' writes stay in the copy (`keep_writes`) are remembered and the widening stops short of them; ranges shaders are writing still go through the busy split. This generalises what #2172 does for marked UAV refreshes to every refresh.

Measured in the intro cutscene (diagnostics build):
- before: copies 290-395 ms, 550-690 MB per frame; 700-730 ms/frame
- after: copies 69-108 ms, 73-120 MB per frame; 380-445 ms/frame

New test `a_partial_refresh_takes_the_whole_page`; the copy-stats line reports bytes taken from whole and partial pages. On main 63bcca4: victory-gpu lib tests 230 passed (`dynamic_slots_are_held_until_released` and `lists_share_a_table_and_copies_keep_their_views` fail on main as well on this RTX 4060 Ti); clippy clean with and without `diagnostics`.

### Review (CHANGES_REQUESTED) by @AndyLatimer — 2026-11-27T08:47:59Z

<https://github.com/Marvisak/VIctory/pull/3289#pullrequestreview-6085580075>

Reviewed commit `6d3e953` (`crates/victory-gpu/src/shadow.rs`, rebased/merged cleanly onto `63bcca4`). The core idea of guarding whole 64 KiB pages on partial refreshes makes sense, but two issues need addressing before merge:

### 1. Partial widening on pages with `kept` writes amplifies repeated refreshes, and `self.kept` is never pruned

`watch::Tracked::take_split(from, to)` only marks a 64 KiB page `p` as guarded (`whole`) when `(p * PAGE).max(self.start) >= from && ((p + 1) * PAGE).min(self.end) <= to`.

When `self.kept` contains e.g. `[p + PAGE - 16, p + PAGE)`, `Shadow::widen(p + 64, p + 80)` clamps to `(p, p + PAGE - 16)` (`65,520` bytes). Because that page is not covered whole, `take_split` leaves it unguarded/dirty, so every subsequent 16-byte refresh on that page re-copies `65,520` bytes instead of `16` bytes on `main` (up to ~4,095x amplification).

In addition, `self.kept` is never cleared once title memory and the host copy resync (`update_tracked`, `copy_back_or_not` with `back == true`, `copy_back_marked`), so a single `keep_writes` permanently prevents whole-page guarding on that page for the rest of the run.

**Reproduced on `6d3e953` (RED):**
`shadow::tests::repeated_small_refreshes_beside_kept_writes_do_not_amplify_copies` failed:
```text
4 small refreshes beside kept write copied 262080 bytes (partial widening re-copies the page)
```
(Expected `<= 64` bytes.)

### 2. Withheld `copy_back_marks` pages are not recorded in `self.kept`

In `copy_back_marks`, pages withheld in `held` call `crate::memory::drop_withheld(page, PAGE)` without recording `[page, page + PAGE)` via `copy.remember_kept(page, page + PAGE)`. A later small refresh at another offset on that same page widens across the whole 64 KiB page and overwrites the withheld GPU writes with stale title memory.

**Reproduced on `6d3e953` (RED):**
`shadow::tests::widened_refresh_preserves_withheld_marked_write_on_same_page` failed:
```text
assertion `left == right` failed: withheld marked GPU write on the same page was overwritten by widened refresh
  left: 0
 right: 221
```
(`0xdd` written at `p + 4096` overwritten by a small refresh at `p + 64..p + 80`.)

### Suggested fix & verification

- In `Shadow::widen`, check `has_kept` per boundary page (`first_start..first_end`, `last_start..last_end`) so pages containing kept writes stay narrow while clean neighbor pages on multi-page refreshes still widen.
- Add `Shadow::forget_kept(from, to)` and prune synced spans in `copy_back_or_not` (when `back == true`), `copy_back_marked`, and `update_tracked` (for each copied/zeroed `(a, b)` span).
- In `copy_back_marks`, collect `(Arc<Shadow>, usize)` pairs for `held` pages while holding `marks()`, drop `MARKS`, and call `copy.remember_kept(page, page + PAGE)` before `crate::memory::drop_withheld(page, PAGE)`.

A local benchmark at `6d3e9539` against `main` `63bcca4` (same base), Windows 11, RTX 3070 PC, release. It is an ignored test in `shadow::tests`, not proposed: one 32 MiB copy over `pool(512)` memory, `copy.update` called directly, and the same random sequence on both trees, 30 frames, 3 runs each (identical every time).

| scenario | `main` | this PR |
|---|---|---|
| **A.** 400 refreshes a frame of 16-256 B at random places, 16 random pages written by the "title" a frame | 0.02 MB copied, 0.12-0.14 ms a frame | 0.97 MB, 0.13-0.15 ms |
| **B.** your pattern: 400 refreshes a frame of 4-32 KiB over a hot set of 64 pages, 2 pages written a frame | 2.84 MB, 0.27-0.28 ms | **0.13 MB, 0.020 ms** |

B is the pattern the description measures in the title: a page cut by a refresh stays changed on `main` and is copied again at every later refresh. Here the PR copies 22× fewer bytes and is about 14× faster. That reproduces the effect away from the title.

A shows the other side of the widening. When the refreshes are tiny and land on pages the title writes, `main` copies only the asked bytes, while this PR copies the whole 64 KiB page once after each write. That is about 50× the bytes at no measurable cost here (both under 0.2 ms, the bytes still under 1 MB a frame). For a title that writes many pages each frame and refreshes only a few bytes of each, the cost would grow with the pages written. That is worth keeping in mind against the 410-550 MB the widening removes in the title. Not a reason to hold it, as far as these numbers go.

`cargo test -p victory-gpu --lib shadow::tests::` at the PR head: 11 passed, 0 failed in each of 3 runs, `a_partial_refresh_takes_the_whole_page` and `overlapping_kept_writes_remember_their_union` included.
