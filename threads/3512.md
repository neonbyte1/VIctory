# Marvisak/VIctory#3512: GPU: a heap sync leaves out the slots past the host heap

- PR by @neonbyte1, opened 2026-11-27T12:04:08Z, state **open**
- <https://github.com/Marvisak/VIctory/pull/3512>
- Archived copy; the original thread is authoritative while it exists.

## Description

## What's wrong

`descriptor::sync_heaps` (`crates/victory-gpu/src/descriptor.rs:169` on `main`) takes each dirty
64 KiB page of a shader-visible heap the title writes as bytes and clamps its last slot at the
**title's** descriptor count only:

```rust
host.sync_slots(first as u32, last.min(u64::from(heap.desc.count)) as u32, start, step);
//                                             ^^^^^^^^^^^^^^^ the title's count, descriptor.rs:196
```

`HostHeap::sync_slots` (`host.rs:695`) then reads every record in `first..last` (`host.rs:699`),
compares each against the slot's `made` key, and calls `self.mirror` for the ones that differ
(`host.rs:714`). `HostHeap::mirror` refuses every index at or past the host heap's count before it
reads anything at all (`host.rs:723`).

The host heap has fewer slots than the title's whenever the host caps its heaps
(`host.rs:145-171`): on NVIDIA `CreateDescriptorHeap` refuses `count + DYNAMIC` and then
`count + MIN_DYNAMIC`, and the cap branch (`host.rs:164`) keeps
`count = PORTABLE_VIEWS - MIN_DYNAMIC` = **934,464** slots, while the title's heap is
**1,245,184** slots (#2121, #3475). The last **310,720** title slots have no host slot, and the
sync reads them and calls `mirror` on every one it finds stale, every frame.

Measured on the same sync code on the `perf/best` lineage (run `0763-heapdirty1`; the host counted
762,920 slots there): of the 222 dirty pages a world frame marks (455,597 slots), **98 pages —
200,704 slots, 44 % — lay past the host's count, and every one of the ~200,000 `mirror` calls made
nothing** (216,049 slots were stale; of the 254,608 scanned below the count, 15,345 — 6 % — needed
making).

`main` has no split heap: one `host: OnceLock<Option<host::HostHeap>>` per title heap
(`descriptor.rs:59`), made with the title's count (`descriptor.rs:100`), so `host.count()` is the
whole bound and there is no per-split arithmetic to redo.

## The fix

Both places stop at `HostHeap::count()`:

* `sync_heaps` clamps the page's slot range with `host::host_slots(host.count(), first, last)`
  before `sync_slots` reads anything, and the `SyncSlots` diagnostics counter counts the slots
  actually scanned instead of the title's.
* `sync_slots` clamps again, and returns before the record read when a range is entirely past the
  count: the invariant does not depend on the caller.
* `host_slots` is the one expression both use, and what the test pins.

No behaviour change: `mirror` never made such a slot. The heap's highest title slot still goes to
`mirror` once per heap per sync, so the `title slot past the host heap` warning (`host.rs:728`)
keeps firing exactly as it does now (once per new highest index); what goes away is the record read
and the refused `mirror` call for the other 310,719 slots.

count keeps the caller's range, one straddling it stops at the count, one past it is empty and
`sync_slots` returns before reading a record; pinned with `main`'s capped numbers (934,464 of

## In game

Measured on an RTX 5090 (driver 620.73.04), Linux, GE-Proton11-14 Wine with its vkd3d-proton, GTA VI's opening prison yard, warm caches, diagnostics build, 420 s runs, medians of the last 30 frame-rate lines. The measured build is the same clamp on our test stack (`main` plus the unmerged PRs we need on NVIDIA under Wine; listed in #3425), where the host heap counts 762,920 slots; candidate and control alternated A-B-A-B.

| | control | with the clamp |
|---|---|---|
| slots the sync reads per frame | 463,995 | 272,778 (−41 %) |
| stale slots handed to `mirror` per frame | 216,049 | 16,236 (−93 %) |
| heap sync (`SyncHeapsUs`) per frame | 19.9 ms | 16.3–18.6 ms (about −2.4 ms) |
| frame, mean of two runs each | 223.3 ms | 218.5 ms (within run-to-run spread) |
| pictures at frames 1700/2048 vs the adjacent control | — | 0.2–0.9 % of pixels off by more than 32 (same lighting) |

The frame-time difference is inside our run-to-run spread, so the counters are the claim: the sync does about 40 % less reading and 93 % fewer refused `mirror` calls. The remaining heap-sync time is mostly waiting on the `SHADER_HEAPS` lock rather than per-slot work, which this PR doesn't touch. On that build the `title slot past the host heap` warning stopped appearing; the version here keeps one past-count `mirror` per sync on purpose, so on `main` it keeps firing as before.

## Overlap with open PRs

`gh pr list -R Marvisak/VIctory --state open --search "heap count" / "sync_slots" / "past the host
heap"`: nothing open makes `main`'s sync stop at the host's count as its own change.

* #3055 (draft, "Part 3 of 3", queued behind #3139) rewrites `sync_slots` into `sync_ranges` and
  clamps each range at `self.count` there, keeping one past-cap `mirror` call for the warning. This
  PR is the same two clamps on `main`'s code without the batching rewrite: it composes with
  #3139/#3055 rather than conflicting with them.
* #3139 (Part 1) and #3356 batch and probe the page walk and do not clamp; #3475 turns the cap
  warning into counted statistics; #3052 clamps the read-mark scan, not the heap sync.
