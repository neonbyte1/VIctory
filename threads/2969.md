## Description

Under Wine, `D3DCompile` is Wine's `d3dcompiler_47` (vkd3d-shader's HLSL). It has no methods on writable byte address buffers (`E5005: Method 'Load' is not defined on type 'RWByteAddressBuffer'`), and it ignores `[RootSignature]`, so the blob carries no root signature to create. Every shader VIctory compiles at run time failed there:

- the indirect-argument clamp: `no argument clamp: indirect execution dropped`, after which every indirect draw and dispatch is dropped as `not bounded`;
- the depth twin's 16-bit conversion: `no depth conversion`;
- the tests' own shaders.

On Linux this alone keeps the world from drawing. In a run on `main` with the NVIDIA fixes below, indirect drops summed to about 5,000 a frame, including the mesh dispatches that carry the world's geometry.

**What changes**
- A new module, `compute`, compiles a shader and builds its root signature in Rust from the parameters the host binds.
- The clamp keeps `main`'s design: one group, tiles of 64, groupshared costs charged in order, the list's budget, the rest of each record copied. The title's records are now a `StructuredBuffer<uint>` (t0), and the clamped records and the budget are `RWStructuredBuffer<uint>` (u0, u1), indexed in words. `bound()` already refuses addresses and strides that aren't multiples of 4. The root signature is b0 (4 constants), SRV t0, UAV u1, UAV u0, in the order `bound()` binds them.
- The depth conversion indexes its scratch buffer in words, with b0 (8 constants) and UAV u0.
- The tests' shaders drop their `[RootSignature]` attributes the same way. The marked-write test ORs its page bit through a `RWStructuredBuffer<uint>`.
- A new test checks every word the clamp writes for draws, indexed draws, dispatches, mesh dispatches, records past the budget and the budget spent.

The approach is @Mumogg's from #1279 (structured buffers indexed in words, the root signature built beside the shader). #1279 no longer applies to `main`'s rewritten clamp, so this ports it and extends it to the depth conversion. #2093 takes the other route, compiling these shaders on Windows at build time. Either fixes the run-time failure; this one needs no change to the build.

**Tested** on an RTX 5090 (driver 620.73.04), Linux, Wine 11.22, vkd3d-proton 3.1-83 (GE-Proton11-14), with `cargo xtask wine-test` (#1218):
- `victory-gpu` under Wine: 225 passed, 6 failed, against 200/30 on `main` (63bcca4). The remaining 6 are other Wine gaps, fixed elsewhere (#1722, #2101, #2973).
- `pipeline::library::tests::pipelines_load_on_many_threads_at_once` is one of the 6, and it only fails with this PR. On `main` its `RWByteAddressBuffer`/`[RootSignature]` shader doesn't compile under Wine, so it returned early and counted as passed. Now it compiles and runs into vkd3d-proton refusing a non-null empty pipeline library blob, which #1722 fixes. With #1722 on top, all 11 `pipeline::library` tests pass (3 of 3 runs).
- In game, on our NVIDIA/Wine test build: `no argument clamp` and the `not bounded` drops are gone. Indirect drops fell from thousands to about 90 a frame, and draws run from about 800 to 4,900 a frame.
- `cargo clippy --workspace --all-targets` (with and without `diagnostics`) and `cargo xtask policy` are clean.
- Once, in three full `victory-gpu` runs, `watch::tests::a_retake_marks_buffer_copies_alone` hung with the rest of the suite running beside it. It passed 10 of 10 runs on its own, both with and without this change. Mentioning it in case others see it.

Not tested on Windows. Microsoft's compiler accepts the same HLSL, but I haven't run it.

What I checked:

- **compute.rs**: root parameters built in Rust and serialized via `D3D12SerializeRootSignature` — this removes the `RootSignature` attribute dependency entirely (Wine's d3dcompiler ignores it, so the blob carried no signature to create). Error blobs are still logged on failure.
- **indirect.rs**: byte→word conversions are consistent throughout (`Load(at+4)`→`args[at+1]`, `Store3(at+8)`→`dest[at+2..at+4]` conditional on kind==1 as before); the draw copy-out writes words +2/+3 unconditionally and +4 only for indexed draws, matching Store2/Store3 exactly. The `(stride/4)` indexing is safe because `bound()` refuses non-4-multiple addresses and strides. Root params preserve the RS order: b0, t0, u1 (budget), u0 (dest). `clamped_records_hold_every_word` is a strong test — every output word asserted per kind, budget charged per the cost model, past-budget records run empty while keeping their non-count words.
- **twin.rs**: `(at16 + y·pitch16)/4 + id.x` is exact because each thread owns a 2-pixel pair in one word; `x*4` bytes = `x` words on the 32-bit side. Round-trip constants unchanged (0x37800080 / saturate*65535+0.5), so the tiled-lighting EQUAL-float behavior is preserved.
- **memory.rs test pipelines**: table/root-view/constants params match the old RS strings register-for-register, including space=2 placements and unbounded ranges.

Note (non-blocking): several test-only shaders still use `RWByteAddressBuffer.Store` (e.g. `dst` in bindless/memory tests) — under Wine those tests would still not compile, which is presumably #2973's scope. Runtime paths are all Wine-safe now.
