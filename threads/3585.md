# Marvisak/VIctory#3585: GPU: a refresh batch takes the written pages of all its copies in one round of the guard lock

- PR by @neonbyte1, opened 2026-11-27T19:07:59Z, state **open**
- <https://github.com/Marvisak/VIctory/pull/3585>
- Archived copy; the original thread is authoritative while it exists.

## Description

## What's wrong

A submission's refreshes are batched per copy (`Batch`, `crates/victory-gpu/src/host.rs:2399`), but `Batch::flush` (`host.rs:2440`) then brings each copy up to date on its own: `shadow.update(from, to - from)` per copy (`host.rs:2447`) → `Shadow::update_tracked` (`shadow.rs:607`) → `Tracked::take_split` (`watch.rs:478`). Each take with a written page in its range takes the global guard lock (`watch.rs:503`), guards the pages' other mappings, makes the pages read-only and drops them from the copy's changed set.

The copies only ever read pages recorded as written, so the volume is small (~130 MB a frame here). The cost is the lock: a world frame makes one round of `watch::GUARDS` per copy with written pages, **3,229 rounds a frame** in our runs. The title's write-fault handler and marked copy-back hold the same lock, so these rounds mostly wait: 7.8 ms a frame in `change checks: … waiting for the guard lock`, on the submitting thread, before `ExecuteCommandLists`.

(The `copies per frame` line's `MB checked` — 6.3 GB a frame here — is the span asked, not bytes compared: `take_split` looks only at the copy's set of written pages in it.)

## The fix

`Batch::flush` works in three phases:

1. **Look up** (`shadow::plan` → `Tracked::written`): for each copy, the written pages in its asked range, read under the copy's own set lock only. A copy with nothing written there stops here. Memory that is not tracked is copied whole, as before.
2. **Take once** (`shadow::refresh_planned` → `watch::take_written`): the whole pages of all copies, sorted and deduplicated, in **one hold of the guard lock**. Each page's other mappings are guarded once, consecutive pages across copies share one `VirtualProtect`, then each copy's set drops the pages taken.
3. **Copy** (`Shadow::copy_taken`, the former tail of `update_tracked`): per copy, one copy per contiguous run, zeros for unmapped runs, untracked parts whole, snapshot sync where this submission's shaders write.

`Tracked::take_split` is now `written` + `take_written` for one tracker, and `Shadow::update` is `plan` + `refresh_planned` for one copy, so there is one take and one refresh path. No switch: the guarantee is the one a single take gives (below), the existing take tests now run through `take_written`, and the change was measured in the title behind a switch first.

**Why no write is missed.** A page leaves a copy's set only under the guard lock, once it is guarded at every mapping (pages that can't be guarded stay changed and are still copied). Copies are read after the take. So a title write before the guard is in the copy; a write after it faults and marks the page again. Writers that don't fault (kernel reads, DirectStorage, remaps, copy-back) mark under the guard lock, so before the page leaves the set (it's in the copy) or after (it's changed again). A page written between the look-up and the take isn't in the plan and stays changed. A page only partly in the asked range is copied in part and stays changed. The window between take and copy is longer than before, but correctness never depended on its length.

The copies line gets `N guard-lock rounds` next to the guard-lock wait (`C::TakeRounds`, diagnostics only).

Run splitting looks up unmapped pages by binary search, removing the O(n²) `unmapped.contains` that #3156 also fixes.

## Tests

CPU only, `watch.rs`:
- `a_batched_take_takes_the_written_pages_of_every_tracker`:
  - nested, overlapping and mid-page trackers in one take each get their runs;
  - one guard-lock round; 8 consecutive pages in one protection change; a page two trackers share guarded once (3 calls for pages 1, 3 and 6);
  - pages outside an ask, and partial pages, stay changed;
  - a page written between look-up and take stays changed;
  - a write to an open page before the take is covered; a write after it faults.
- `batched_refreshes_under_concurrent_writes_lose_no_write`:
  - 8 writer threads over a 32-page pool and both mappings of twin views;
  - 7 overlapping trackers (one starts mid-page, one ends mid-page, two on the twin views);
  - 300 rounds of batched refreshes over random asked ranges, copying what each take returns;
  - afterwards, every page where a copy differs from title memory is still changed, and one last refresh leaves every copy equal and clean.
- Deliberate bugs, each caught:
  - take without guarding (`taken = whole`): both tests fail;
  - drop pages only partly asked from the sets: the concurrent test fails.

GPU, skipped without a device: `host::batch::overlapping_copies_in_one_batch_each_take_the_written_pages` (two overlapping copies in one batch, each gets its written pages; a later write is seen by both). The existing `a_copy_is_refreshed_once_per_submission_by_the_pages_written` covers one copy.
