# Marvisak/VIctory#3091: HLE: Winsock overrides work when the host lacks newer exports (Wine)

## Description

Split out of #2973, as asked in its review.

`victory-hle`'s Winsock overrides resolve `WSAConnectByList` and `GetAddrInfoExA` from the host's `ws2_32.dll` when the module loads. Wine's `ws2_32` doesn't export them, so loading failed and every test that goes through the overrides failed with it. They are now looked up on first use. When the host has no export, the override refuses the call the way an unreachable network does (`WSAENETUNREACH` for the connect, the existing blocked-lookup result for the name lookup).

The loopback and `resolvable` checks still run before that fallback, so the offline guards are not loosened: nothing reaches the network that couldn't before.

When the host lacks these exports, the call is refused even for loopback targets (`127.0.0.1`, `localhost`): there is nothing to forward it to. On Windows both exports exist, so nothing changes there.

**Tested** (Linux, GE-Proton11-14 Wine, RTX 5090): `victory-hle` tests under `cargo xtask wine-test` (#1218), 152 passed, 1 failed. The one failure is `xgamesave::tests::a_kept_blob_past_the_link_limit_is_copied`, an NTFS hard-link limit that Wine's filesystem doesn't have; #2973 skips it under Wine. I have no Windows machine; on Windows the exports exist, so the overrides behave as before.
