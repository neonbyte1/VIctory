## Description

Test changes so that `cargo xtask wine-test` (#1218) runs the Windows test suite on Linux. **Stacked on #2969**: the first commit here is that PR, so please review from `GPU tests: a capped view heap keeps its documented size` on. I'll rebase it out once #2969 is decided.

The runtime fixes this PR used to carry are now separate:
- **#3091** Winsock overrides without the newer host exports
- **#3092** crash records stay whole
- **#3093** the shader tests share one D3D12 queue per adapter, so the change to every GPU test can be reviewed on its own
- The empty pipeline library fix was already in **#1722**, so it's dropped here.

**What's left here** (tests that assumed Windows or particular hardware):
- **Capped view heap.** A capped view heap keeps the size the code documents (vkd3d-proton on NVIDIA allows at most 1,041,451 slots). The test now asks the host for a full heap first.
- **Host capabilities.** `hosts_that_do_not_fuse_are_named` still asserts on Windows that WARP doesn't fuse FMad. Under Wine, "WARP" is vkd3d-proton, which does fuse, so the test reports it instead. The null-buffer-view probe is skipped only where the host can't make the heap.
- **Present test.** It waits for the host queue after presenting. Under Wine on NVIDIA, a process that exits right after its first present can hang in the driver's exit handler (HansKristian-Work/vkd3d-proton#3524).
- **Skipped under Wine, each printing why:**
  - the two page-table memory tests: Wine's compiler has no shader model 5.1 resource arrays (`E_NOTIMPL`);
  - the NTFS hard-link limit test: Wine's links go to the host filesystem.

**Results** under Wine 11.22, vkd3d-proton 3.1-83 (GE-Proton11-14) and DXVK `dxgi`, on an RTX 5090 (driver 620.73.04), with #1218 merged for the runner (passed / failed):

LGTM — reviewed the stack on top of #2969 (8db914232..cb61564dc).

The three real fixes check out:

- **Null-blob pipeline library**: `bytes.is_empty() → null` is the correct fix — an empty Rust slice's pointer is non-null, and vkd3d-proton rejects a non-null pointer with zero length. The raw-vtable `CreatePipelineLibrary` call with `ID3D12PipelineLibrary1::IID` + `from_raw` is sound.
- **Winsock lazy lookups**: refusing with `WSAENETUNREACH`/`WSAHOST_NOT_FOUND` + a `once()` log preserves the console-without-network answer instead of panicking; the export-presence test correctly moves these into `HOST_MAY_LACK`.
- **Crash-record append lock**: bounded try-lock (10 ms) that still writes on timeout is the right trade-off for an exception context — a rare interleave beats a deadlock or a lost report; poisoned guards are taken via `into_inner`.

Test-side changes verified:

- `wait_idle` bumps `submitted` under its lock before Signal — no fence-value collision with the submission path; the queue.rs present-test wait matches the documented vkd3d-proton#3524 hang.
- Shared `SharedDevice {device, queue}` per adapter: command queues are free-threaded, WARP stays serialized, and the vkd3d fence-thread teardown motivation is real. Acceptable consequence: a device-removed event would now persist across tests — in practice that's fatal for the run anyway.
- `under_wine()` via `wine_get_version` is the standard probe; both uses are cfg(test)/test-only.
- Heap-cap probes in descriptor/host.rs and stride_tests.rs ask for the real heap before asserting/skipping — better than name-matching adapters; the (4 + MIN_DYNAMIC) capped assertion pins the documented behavior on NVIDIA.
- The FMad test now reports rather than asserts under Wine — correct, since vkd3d's WARP legitimately differs from Microsoft's rasterizer.
