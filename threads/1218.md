## Description

Adds `cargo xtask wine-test`, which runs the Windows test suite on a Linux host under Wine. Several testers in #340 do this by hand today.

### What it does
- Cross-builds for `x86_64-pc-windows-msvc` with `clang-cl`, `llvm-lib` and `lld-link` against an `xwin splat` (default `~/.xwin`). The toolchain is set through environment variables only, so Windows builds and `.cargo/config.toml` are unchanged.
- Runs the tests with `wine` as the target runner, in a Wine prefix of its own under `target/wine-prefix`. The user's `~/.wine` is not touched.
- `--vkd3d-proton <dir>` copies that folder's `d3d12.dll` and `d3d12core.dll` into the prefix and overrides Wine's own D3D12, which lacks shader model 6.6. vkd3d-proton's pipeline cache goes to `target/vkd3d-proton-cache`; written to the crate directory, the asset policy would reject it.
- Default arguments: `--workspace --exclude xtask --no-fail-fast`. xtask runs `git`, so it stays a host-only tool. Arguments after `--` replace the defaults.
- `victory-loader`'s two end-to-end tests in `tests/load_probe.rs` build their fixture by running `cargo`, which they cannot do inside Wine. The default run skips them (`-- --skip ...`) and says so. The prebuilt-fixture hook (`VICTORY_HLE_PROBE`) is split out into #3270; with it set, the skips are left out.
- README: a short paragraph under Getting started.

### Result on this branch
Measured before the hook was split out (the run included the two loader tests through the hook), on `main` of that day, Wine 11.22, vkd3d-proton from GE-Proton11-14, RTX 5090: **334 passed, 4 failed, 6 ignored**. The four failures are known Wine/vkd3d-proton gaps with open fixes:

## The default path exits before running anything

With the loader hook moved to `pr/hle-probe`, `wine-test` now skips the two tests instead. When `VICTORY_HLE_PROBE` is unset the command assembles to:

```
cargo test --target x86_64-pc-windows-msvc --workspace --exclude xtask --no-fail-fast \
           --skip loads_binds_and_calls_probe --skip maps_a_title_dll_the_title_loads_itself
```

There is no `--`, so `--skip` is read as a cargo option, and cargo has none:

```
$ cargo test --locked -p xtask --no-run --skip some_test_name
error: unexpected argument '--skip' found

  tip: to pass '--skip' as a value, use '-- --skip'

Usage: cargo.exe test --locked --package [<SPEC>] --no-run [TESTNAME] [-- [ARGS]...]
```

`cargo test ... -- --skip some_test_name` is accepted. Checked on cargo 1.98.1, the pinned toolchain; it is cargo argument parsing, so no Wine or Linux behaviour is involved and the result should hold on a Linux host.

```rust
test.args([
    "--",
    "--skip", "loads_binds_and_calls_probe",

]);
```
