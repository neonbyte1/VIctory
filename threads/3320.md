# Marvisak/VIctory#3320: GPU: back indirect arguments in VRAM, use RwLock for SHADER_HEAPS, and batch copy_back_marks

- PR by @danielibabet, opened 2026-11-26T17:42:04Z, state **open**
- <https://github.com/Marvisak/VIctory/pull/3320>
- Archived copy; the original thread is authoritative while it exists.

## Description

### Summary
Three independent CPU/GPU contention and barrier fixes on top of `main`:
1. **VRAM-backed indirect argument buffers + drop redundant post-clamp UAV barrier (`indirect.rs`, `host.rs`)**
   - Add `Host::uav_buffer` (`D3D12_HEAP_TYPE_DEFAULT`, `ALLOW_UNORDERED_ACCESS`, `COMMON`) and back `HostList::arguments` in VRAM instead of `L0` system memory (`shared_buffer`), avoiding PCIe round-trips for both `clamp` UAV stores and `ExecuteIndirect` reads.
   - Remove the redundant `uav_barrier()` (`pResource = None`) right before transitioning `out` from `UNORDERED_ACCESS` to `INDIRECT_ARGUMENT` in `indirect::bound` (the resource transition already synchronizes `out`, and the next `bound` call issues the pre-dispatch `uav_barrier()` for `budget`).
   - Update `indirect::tests::clamped` and `argument_buffers_move_from_their_current_states` to read back `out` via `readback`.
2. **Eliminate `SHADER_HEAPS` mutex contention during descriptor mirroring (`descriptor.rs`)**
   - Switch `SHADER_HEAPS` from `Mutex` to `RwLock`: `mirror` (title threads), `sync_heaps` (submission thread), and all read-only queries take `.read()`, while `Drop` and `create` take `.write()`, so `sync_heaps` no longer stalls title threads writing descriptors (`MirrorWaitUs`).
3. **Reuse scratch buffer and batch `Tracked::taken` in `copy_back_marks` (`shadow.rs`)**
   - Reuse a single `pooled(PAGE)` scratch buffer across all marked pages in `copy_back_marks` instead of heap-allocating and zeroing `vec![0u8; n]` per 64 KiB page.
   - Batch `t.taken(&list)` once per `Shadow` instead of calling `VirtualProtect` / taking the `GUARDS` lock page by page.

### Comment by @KainanP — 2026-11-27T11:53:59Z

<https://github.com/Marvisak/VIctory/pull/3320#issuecomment-7217603700>

One concern with the `copy_back_marks` batching at head `3afe123b` (read from the code, not run).

**A title write can be lost between a page's copy-back and its batched `taken`.**

- `shadow.rs:525-530`: when `copy_back_marked` writes page P back, it holds `watch::writing(from, n)`. `Drop for Writing` (`watch.rs:786-793`) calls `changed()`, which marks P changed and gives it write access back. The page is then only pushed onto `synced`.
- `shadow.rs:959-971` / `:980-985`: `t.taken(&list)` runs only when the loop reaches a page of another `Shadow`, or at the end. `taken` (`watch.rs:545-560`) protects the pages and then does `changed.remove(&page)` and `self.changed.taken(page)`.

Scenario: P is copied back and left open. The loop goes on to P+1 … P+k of the same `Shadow`. Each of those costs a 64 KiB `read_into`, a compare or merge, maybe a `write_mapped`, and two guard-lock rounds. Meanwhile a title thread writes P. P is open, so there is no fault and the write isn't recorded anywhere. Then `taken([P, …])` clears P's changed mark. The host copy keeps the shaders' bytes and never picks up the title's write. Nothing re-marks it later, because the page is guarded again and clean.

`main` has the same race. There, though, `taken` runs right after each page's write, so the window is a few microseconds. Here it lasts as long as the rest of that `Shadow`'s marked pages take, which can be thousands of pages per frame on the scenes in #3425.

Possible fixes, keeping most of the gain:
- Call `t.taken(&[page])` right away for pages where `written.is_some()`, and batch only the pages that were already equal (those were never opened, so there is no window).
- Or hold the `Writing` guards until the batched `taken`, so P stays in `busy` and a title write is seen through `changed`. This needs checking against `protect`'s `busy` filter, which would then skip P.
