## Description

A diagnostics switch that plays a scripted gamepad timeline, so a headless run can move the character without a real controller or window focus:

```
VICTORY_SCRIPTED_INPUT='1500:back;1800:look_left;1860:fwd;2400:off'
```

Each entry sets the pad from that presented frame until the next entry. It's keyed on the frame token that `victory_gpu::frame` present logs show. The states:
- left stick: `fwd`, `back`, `left`, `right`;
- right stick: `look_*`;
- triggers: `lt`, `rt`;
- buttons: `a`/`b`/`x`/`y`, `menu`, `view`, `lb`/`rb`/`ls`/`rs`, and the d-pad (`du`/`dd`/`dl`/`dr`);
- `off` releases everything.

States combine with `+` (`fwd+look_right`). The script overlays a connected pad, or the keyboard stand-in pad when none is connected.

**How it relates to `VICTORY_KEYS`:** `VICTORY_KEYS` (and #3239's holds and repeats) is timed in seconds and goes through the keyboard path. This one is timed in presented frames and sets pad state directly. At about one frame per second, wall-clock timing lands at different points of the game from run to run, while frame-keyed timing is repeatable. The README row says so next to `VICTORY_KEYS`.

**Changes:**
- **`gameinput.rs`:** the parser, the timeline lookup, and the overlay in the poll, plus three unit tests: parsing, segment lookup, and the overlaid reading.
- **`frame.rs`:** a diagnostics-only accessor for the frame number.
- **`README.md`:** one row next to `VICTORY_KEYS`.

All of it is behind `diagnostics`; when the variable is unset, nothing changes.

**In game** (GTA VI on Linux, RTX 5090, GE-Proton11-14, headless gamescope, `main` plus the PRs needed on that setup):
- The script above walked the character back from the cell window from frame 1500, turned the camera from 1800, and walked forward from 1860.
- The hints changed to "Approach a cellmate to interact with them", then "Hold … to interact".
- By frame 2200 the objective was "Go with the prison guard".
- No faults during the run.

**Tested:** the `gameinput` tests pass under `cargo xtask wine-test` (#1218), 13/13, with and without `diagnostics`. Clippy `-D warnings` and `cargo xtask policy` are clean. Not run on native Windows.

### Review (COMMENTED) by @AurumCarlos — 2026-11-26T16:15:43Z

<https://github.com/Marvisak/VIctory/pull/3293#pullrequestreview-6077393313>

Frame-keyed timing is a good complement to `VICTORY_KEYS`, and the `diagnostics` forwarding to `victory-gpu` is already there, so `frame::number()` resolves.

One trap: unknown tokens are ignored but the entry is still kept, so a typo'd entry (`1800:fwrd`, `look_rigth`) becomes a neutral pad and silently acts like `off` from that frame on. In an unattended run that looks like the character just stopped. A `warn!` naming the token (once, at parse time) would make that obvious; and `scripted_input_timeline_holds_the_last_state` could pin it.

@AurumCarlos good catch, thanks. Fixed in `56dcd63`. An entry with an unknown token is now dropped whole, so the last valid state stays active, and the parser warns once per bad token with the entry text (`unknown scripted input token; entry ignored`).

I chose dropping the whole entry over keeping the recognised tokens: applying `fwd` from `fwd+bogus` would invent a state the script never asked for, and a lone typo would still look like `off`.

The timeline test now includes `40:fwd+bogus` and `50:look_rigth`, and checks that the previous state (`back`) is still active at frame 49. A second test checks that a bad token is reported once. The `gameinput` tests pass under Wine (14/14), and clippy, policy and formatting are clean.
