# Marvisak/VIctory#2118: GPU: the BVH builder runs whole or not at all

## Description

## The problem

A frame can run only part of the title's ray-tracing structure builder. The stages that run then write wrong results into title memory. In fxceless/victory-fork this wrote garbage bounds and crashed the title.

The title's BVH builder (`XboxBvhBuilder.dll`) builds and refits its ray-tracing structures in title memory through about fifty compute dispatches a frame. A dispatch without a host pipeline is dropped on its own while the rest of the list runs (`State::dispatch`). Some builder pipelines lack one:

- refused on NVIDIA (they ask for 64-lane waves);
- not translated;
- still being made.

So the stages that do run work on data the missing stages never produced.

## The fix

Builder dispatches run only in frames where every builder pipeline has its host pipeline. Otherwise none run, and the structures keep what they held. The decision is made once per frame (`pipeline::builder::runs`), so no frame runs part of the builder.

- Builder pipelines are recognised by origin: their bytecode lies in the builder DLL's image, or the builder's code is among the callers when the pipeline is created. `run` registers the DLL's range when it maps it (`note_title_dll`, at start and when the title loads it later).
- They start compiling as soon as they are created, so the per-frame wait budget does not hold the builder back.
- Both direct dispatches and indirect dispatches (`execute_indirect`) of a held-back builder pipeline are dropped.
- A builder dispatch dropped at dispatch time although its pipeline is made (`State::bind` fails, e.g. a root view's offset it cannot place; or an indirect dispatch's arguments, count or signature are missing) also holds the builder back: at once for the rest of the frame, then for as long as the title keeps that pipeline. It is not retried on a timer, since the drops seen recur every frame and each retry would be another partial frame. A builder pipeline created after the frame's decision and not yet made holds only the rest of that frame; the next frame's check sees it as missing. Skipped pipelines (`VICTORY_SKIP_PIPELINES`, diagnostics) were already covered: they count as refused.
- The log says when the builder starts or stops running, and why (`dropped=` counts pipelines held for a dropped dispatch). The first dropped dispatch is logged with its reason.

On NVIDIA this keeps the builder off until 64-lane programs run there, instead of running it partly. Pipelines from other code are not affected. The rule comes from fxceless/victory-fork's notes; the code is new.

## Testing
