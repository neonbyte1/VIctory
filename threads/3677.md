# Marvisak/VIctory#3677: GPU: whole pages a copy's shaders wrote stay in the copy until a touch (VICTORY_OWNER, opt-in)

- PR by @neonbyte1, opened 2026-11-28T05:42:41Z, state **open**

## Description

## What's wrong

At the end of a submission, every 64 KiB page shaders marked as written goes
back into title memory (`crate::shadow::copy_back_marked`): read the page
through the kernel, compare it with the copy's bytes from before the
submission, write back what differs. Most of that work is thrown away. A
census of the pages written back on our integration tree (the switch that
names who first touches each page, `VICTORY_OWNER_CENSUS`) found that
**87 % of them are overwritten by the GPU before anything reads them**; of
the rest, the first toucher is mostly our own copy-back of another copy.

## The change

`VICTORY_OWNER=1` (off by default) leaves a whole page the title did not
write in its copy instead of writing it back:

- Title memory keeps its older bytes behind `PAGE_NOACCESS`, and the copy
  keeps the bytes that go back.
- The first touch gives the page the copy's bytes *through the runtime's own
  writable view of the page's section* (`Section::whole`, reported to the GPU
  side with `set_writable_alias`), while every title mapping still has no
  access: no reader ever sees the old bytes.
- Who counts as a touch, and how each gets the page's bytes first: in-process
  reads and writes (they fault into the existing vectored handler, which
  resolves the page before the access retries; a read fault on a page that is
  readable again — another thread resolved it, or a mapping replaced it —
  continues); our kernel reads (`host::read_into`/`copy_mapped` serve the
  bytes from the copy without writing title memory); kernel writes
  (`watch::writing`); DirectStorage's writes into physical pages
  (`xmem::will_write`, *before* the bytes land, then `report_written` after);
  the runtime mapping or unmapping memory; the copy going (`Shadow`'s drop);
  and a withholding (`Shadow::withhold`).
- The count of held pages is raised before a page loses its access and
  lowered only after it is readable again, and a page that cannot be guarded
  again is left readable: a count of zero never covers a page with no access,
  so the handler's lock-free early out and `serve` either take the lock and
  find the page readable, or serve a page that is still held.
- A page its shaders mark again before any touch is never written in between:
  the copy already holds the newest bytes (`owning`/`again`), the other
  holders are marked changed with the page's bytes kept first, and *this
  copy's* armed held pages keep their bytes at arming (`arm_keeping`) so its
  own copy-back merges against them.
- A page that cannot stay in the copy (the title wrote it during the
  submission, it is not guarded, it is shown at another address, or its
  section has no writable view) is written back through that same view, and
  every other holder of the page and of its other mappings is marked changed
  with its bytes kept first: the title's mapping is never opened, so a title
  write during the copy faults, waits for the guard lock, and lands after
  ours. A page kept in the copy reports no bytes written.
- Withholdings act on the copy that held the page: a held page the
  submission's shaders wrote goes back by the bytes kept at arming (what
  title memory would have held) and the withheld ones are dropped; a held
  page they did not write goes back by its older, valid bytes. Another copy's
  held page is left to that copy's own copy-back or withholding.
- A page whose mapping was replaced without a report, or whose own view is
  gone, is not written: title memory keeps its bytes and its copy reads them
  again. No *new* page is kept while a later submission may be writing its
  copy (`VICTORY_GPU_OVERLAP`), and a released title buffer gives its held
  pages back at `shadow::unregister`.

With the switch off nothing is kept: the added costs in the default path are
one relaxed atomic load per `read_into`/`changed`, and for a read access
violation one relaxed load (the switch) before the handler gives up.

## What the switch needs to do anything

Pages must be section-backed (the runtime's physical-page views) so a
writable view of the page exists. Title memory from the runtime's
write-watched pools is not: it goes back as it does today.

## Known limits

- A copy armed over a page another copy holds can lose its own shader writes
  when both write that page in one submission (it is marked changed, keeps no
  bytes to merge against, and its copy-back then keeps title memory). Our
  fork's `main` avoids this with `mark_others`/`arm_keeping` for every holder;
  that is not done here, to keep the memory `arm_keeping` allocates bounded.
- Withholding through `copy_back_marks`' held-page loop and the
  address-driven path (`memory.rs`) is untested; the tested path is
  `keep_writes` → `Shadow::withhold`. A copy that did not arm a page it wrote
  leaks the withheld bytes there (its held page is resolved instead of
  dropped).
- `arm_keeping`'s cost (64 KiB per armed held page of the copy) is
  unmeasured on this branch.
- Pages already held are still served and resolved from their copy while a
  later submission may be writing it; only *new* pages are refused under
  overlap.
- `owner()` reads the environment on its first call, which can happen inside
  the fault handler (once per process).
- The device tests skip silently when there is no host GPU.
