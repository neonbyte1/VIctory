# Marvisak/VIctory#3313: GPU: count single-list submissions in the GPU timing summary

- PR by @neonbyte1, opened 2026-11-26T17:08:11Z, state **open**
- <https://github.com/Marvisak/VIctory/pull/3313>
- Archived copy; the original thread is authoritative while it exists.

## Description

`VICTORY_GPU_TIMING=1` splits a host submission into one group per host list, but `gpu_times()` ran only when a submission had more than one group. A submission with exactly one host list was counted in the fps line's `on the GPU`, but was missing from `GPU timing: lists ... their commands ...`.

**This change:**
- calls `gpu_times()` whenever timing is on, including for single-list submissions. The slow-list and device-removed checks still apply only to multi-list submissions, which is what they're about.
- reads the preparing/GPU/copy-back counters in the 5 s block where `log_gpu_times()` runs, so those parts of the fps line and the `GPU timing` line cover the same frames. Before, those counters were swapped every ~1 s. `fps`, `ms/frame` and `draws/frame` on that line still describe the last 1 s.

- (by @andrewpozdnakov7-jpg, `7592bb4`) records the timestamp queries and labels whenever timing is on, not only with DRED, so `VICTORY_GPU_TIMING=1` alone gives per-command times. The GPU breadcrumb markers stay DRED-only, and with DRED on the path is unchanged. It also adds an opt-in WARP test (`timing_report_uses_each_submitted_list`, ignored by default).

Nothing changes when timing is off: then each submission is a single group, and that path is untouched.

**Measured** on an RTX 5090 under Wine (vkd3d-proton), GTA VI's opening yard. The build is `main` plus a few unmerged PRs that this setup needs, with this commit cherry-picked unchanged:

| | `GPU timing: lists` | fps line `on the GPU` |
|---|---|---|
| without this change | 358–370 ms/frame | ~465 ms/frame |
| with it (4 consecutive reports) | 742.0 / 749.4 / 753.7 / 765.5 ms/frame | 751.2 / 757.7 / 762.6 / 796.9 ms/frame |

Without the change, about 100 ms/frame of GPU work (≈9.5 single-list submissions per frame in a diagnostics count) was missing from the timing summary and its per-command breakdown. The two runs measure different builds, so compare the gap within each row, not the absolute numbers.

Thanks to @Ingenioeren, who independently found the same single-list gap on WARP in #3028.

**Tested:**
- `cargo clippy --workspace --all-targets -D warnings`, with and without `--features diagnostics`, and `cargo xtask policy`: all clean.
- The in-game run above.

There's no unit test: the condition sits in `Host::execute` after `ExecuteCommandLists` and a fence wait, and `HostList::slowest()` reads DRED timestamps from a live GPU.
