# Marvisak/VIctory#514: fix(gpu): recheck uncommitted blocks before skipping writes

## Description

## Dependency and scope

This follow-up is stacked on #464 at `41af42e`. The additional change is the single commit [`8540a0e`](https://github.com/jeremygold02/VIctory/commit/8540a0ec34234ed35700dd98ce338402f507855e). It keeps the sparse-memory copy optimization and fixes two ways it can miss ordinary writes.

#185 also exercises a partially committed range in its broader shadow-copy implementation. This patch targets the `Guards::absent` cache introduced by #464 and inherited by #490.

After a failed attempt to guard a 64 KiB block, #464 queries its first address. A section can have a reserved first page and a committed, writable 4 KiB page farther into that same block. Marking the entire block absent makes a later write to the committed page invisible to the journal. An ordinary page commit after the first refresh can also go unnoticed if it does not go through the runtime's physical-view remap hook.

The change requires the queried uncommitted region to cover the entire block. Before skipping a previously absent block, the next refresh rechecks the region. Adjacent absent blocks use the same query result for that pass. A failed query or partial coverage leaves the block eligible to be reported dirty.

## Windows verification

- The new regression test uses a reserved section with a committed 4 KiB page inside the second block and commits another page inside the third block after an initial refresh. On #464 the guard omits both dirty pages. With this change it reports both. An independent journal test also confirmed that a later ordinary commit in a private reservation is detected without a runtime notification.
- The existing whole-placeholder test still skips unchanged pages and detects an explicitly notified remap.
- Confirmed the effect in the production shadow refresh path on a physical RTX 5070. Two registered 4 KiB buffers held seed bytes `0x19` and `0x27`. After the guest wrote `0xA6` and `0xB7`, submission through `Host::execute` left both mapped D3D12 shadows at their seed values on #464. With this commit both host shadows contained the new bytes. The synthetic submissions contained no draws or dispatches.
- In a synthetic scan with a committed 64 KiB prefix and a stable 16 MiB reserved tail, main reported 256 redundant dirty blocks per repeat. Both #464 and this branch reported zero. Median journal scan times were 47.60 µs on main, 4.19–4.33 µs on #464 and 8.32–8.76 µs on this branch. These timings cover the journal only.
- The full watch module passed 40 serial runs and 40 four-threaded runs on each revision, with three tests on #464 and four on this branch. Formatting for the changed file and strict library Clippy passed. Clippy with test targets reports the same existing undocumented unsafe block in `host.rs` on #464 and on this branch.

The focused test command is `cargo test -p victory-gpu --lib watch::tests:: -- --test-threads=1`.
