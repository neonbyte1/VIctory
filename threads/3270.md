# Marvisak/VIctory#3270: Loader: VICTORY_HLE_PROBE names a prebuilt hle-probe fixture

## Description

Split out of #1218, as the maintainer triage asked, so that PR stays about the Wine test runner.

`crates/victory-loader/tests/load_probe.rs` builds the `tests/fixtures/hle-probe` fixture by running `cargo` from inside the test. Under Wine, the test process can't start the host's `cargo`, which isn't a Windows executable. With this change, `VICTORY_HLE_PROBE`, when set, names an already-built `hle_probe.dll`, and the test uses it directly. When it's unset, nothing changes.

One commit, one file; no fixture, runner or docs changes.

**Tested** under Wine (vkd3d-proton, Linux, RTX 5090) with the fixture cross-built on the host: `loads_binds_and_calls_probe` and `maps_a_title_dll_the_title_loads_itself` pass. Windows-target clippy (with and without `--all-features`) and `cargo xtask policy` pass. Not run on native Windows, where the variable is unset and the test path is the one on `main`.

_AI-assisted (Claude); measured on my machine, no game data shared._
