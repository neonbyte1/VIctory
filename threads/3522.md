## Description

Part of #3425, the "Descriptor heap mirroring (384k slots), 18.1 ms, `HostHeap::sync_slots`" row.

## Where a changed slot's ~1 µs goes

I timed each step of `HostHeap::mirror` (serialized `rdtsc`, temporary, not in this PR) in the `sync_slots_bench` shape from my [#3425 comment](https://github.com/Marvisak/VIctory/issues/3425#issuecomment-7219063899): 393k slots a frame, ~9.5k changed, 1/8 null views, 1/8 constant buffers, 6/8 placed buffer views. That's the "other" mix #3233 measured in the world, where 68 % of the views made are constant buffers and memory views. Per changed slot on `main`, RTX 4060 Laptop:

| step | ns |
|---|---|
| `bindless::Viewed::set` (the census of what slots view) | **~480-690** |
| of which the slot `HashMap` insert/remove | ~290 |
| of which counting the old range out (`BTreeMap` entry + remove, tallies, hull rebuilt with an `Arc` clone) | ~360 (non-serialized) |
| `make` (`buffer_srv`) | ~310 |
| of which `CreateShaderResourceView` | ~100-140 |
| `keep` (+ `host::retire` of the old resource) | ~100 |
| made/`VIEWS` locks and `view_at` | ~60-100 |
| `prepare` | ~50 |
| stride/address/mark tables | ~35 |

The driver call is only about 10 % of the cost. A host-descriptor cache that turns `Create*View` into `CopyDescriptorsSimple` would save at most ~100 ns of the ~1 µs. The largest single cost is the census bookkeeping.

## Change

- **`Viewed.slots`**: a `HashMap<u32, Seen>` holding the heap's ~600k-1M slots (2^20-2^21 buckets) is replaced by pages of 1024 entries indexed by slot, created when a slot in them is first set. That is one memory access instead of hash probes that miss the cache, and it uses less memory once a heap is mostly set (32 B per slot vs ~37 B per bucket at 2x capacity).
- **`Inner::count`**:
  - Range counts are a `HashMap`. Their order was only read by the `diagnostics` census, which now sorts before `dedup`.
  - Counts and start/end tallies take one lookup each (entry API instead of entry + remove).
  - The new view is counted before the old one goes, so a slot rewritten with the same range never drops to 0 and does no hull work.
  - A copy's hull is updated in place instead of being rebuilt with an `Arc` clone. The key's copy is the same object while `ends` holds it.
- **`HostHeap::keep`**: when the slot gets a view of the resource it already holds, the old reference is not retired. Most buffer views sit on a few host copies. The slot still holds the resource, and any later change retires it as before, so it is freed only after the submissions in flight have run. This drops the `RETIRED` lock and one extra reference per slot until the next submission.

There is no change in what is made. The census's hulls, ranges and textures are identical.

**Diff read (bindless.rs, host.rs):** no correctness problem found.
- `put` counts the new view in before the old one out. Final counts are identical to remove-then-add; a same-range rewrite no longer hits 0, so no hull work. Different ranges are unaffected.
- `count`: the single-lookup entry paths match the old behaviour: a decrement of a missing range is a no-op (old: `saturating_sub` on a fresh 0), `tally` never underflows because entries are removed at 0. The hull is rebuilt only when a range comes or goes, as before.
- In-place hull update keeps the old `Arc`; safe because the key is the copy's pointer and `ends` holds that Arc while any range for it exists; the hull and `ends` entries are removed together. `dirty_bit` is still refreshed.
- `HashMap` ranges: order was only used by `diagnostics`; it now sorts before `dedup` (needed, and done).
- `Slots`: pages of 1024; `retain` does not count ranges down, same as the old `retain` on textures. Notes only: a page is never freed once created, and a bogus huge slot index would size the page vector by `index/1024` (heap indices are bounded, so fine).
- `keep`: skipping the retire when the slot's new resource is the same object is safe: the slot still holds it, and its later replacement retires it after submissions in flight at that time.
